# 庄月空间 UI 交付

把一次页面工作作为“设计确认 → 聚焦实现 → 可验证交付”的闭环处理。

## 开始

1. 阅读根目录 `CONTEXT.md`、相关 ADR、`ui图/UI说明.md` 和 `ui图/交互说明.md`。
2. 判断页面归属：全局工作台/“我的”/系统级子页面共享平台风格；业务模块保留自己的视觉语言。
3. 明确本轮页面边界。用户只指定一个页面时，不顺带改造其他页面。

## 路由

- 涉及新页面方向、风格选择或设计图时，先按 [UI 工作流](references/ui-workflow.md) 完成图稿确认；设计确认前不改页面代码。
- 用户原始请求已包含界面实现，或用户选择了明确写有“开始开发”的确认项时，图稿确认后直接进入代码；只确认图稿不扩展为代码实现。实现仍须遵守 [UI 工作流](references/ui-workflow.md) 的页面范围和风格隔离规则。
- 候选图阶段只生成图稿并维护候选索引，不自动真机预览、提交或推送，除非用户另有明确要求。
- 只有用户给出“可以”“同意”“改吧”“开发吧”“照着改”等无歧义确认，才把候选图视为已确认；这类简短确认只授权上一条消息明确写出的动作，“确认方向”不等于“开始开发”。讨论细节或提出局部修改不算确认。
- 开始实现后即按 [交付流程](references/delivery.md) 实时同步文档并维护 JSDoc；完成检查后自动推送真机预览。Git 提交前先向用户说明分批方案，得到明确确认后再提交并推送。

## 实现原则

- Vue 页面使用 Vue 3 Composition API、`<script setup lang="ts">` 和显式 props/emits；路由页保持组合层，复用逻辑放入聚焦组件或 composable。
- 先保护业务语义和数据安全，再处理视觉细节。微信 API 回调不能替代用户明确确认时，使用可恢复、可测试的状态流程。
- 复用优先：实现组件前先查 uview-plus；库内已有满足业务语义和交互要求的组件时优先复用，包括优先使用 `<u-icon>` 等通用能力，不重复自造同类组件。uview-plus 没有合适组件、真机表现不稳定或无法满足业务边界时，再实现聚焦的项目组件或语义化 `AppIcon`。不要为应用这条规则顺带迁移本轮未涉及的页面。
- 视觉一致：无论使用 uview-plus 还是项目组件，都按当前页面所属的庄月空间视觉语言适配色彩、圆角、间距、排版和交互反馈，不能直接带入与现有页面冲突的组件库默认风格。图片资源按已确认设计或业务需求选用，并处理包体、加载失败状态和隐私边界。
- 实现期间持续维护相关测试、需求/交互说明和当前图稿索引；具体同步时机和代码注释要求以 [交付流程](references/delivery.md) 为准。
- 请求引用 GitHub Issue 时，按仓库规则读取并同步该 Issue；没有 Issue 编号且用户未要求时，不为单次视觉迭代自动创建外部 Issue。

## 用户确认

- 需要用户决定下一步且方案可枚举时，必须给出 `1`、`2`、`3` 等简短编号选项，并明确说明“只需回复数字”；不要改用“需要时回复……”等开放式收尾。真正开放的问题仍直接提问。
- 选项保持互斥、简洁且包含必要影响；推荐项放在最前。二选一时使用 `1. 确认执行`、`2. 取消` 或同等明确文案。
- 交付候选图时，按本轮范围提供必要选项，并把后续动作写进选项，例如 `1. 确认定稿并开始开发`、`2. 仅确认定稿，暂不开发`、`3. 继续调整图稿`；不要让用户猜测“确认”是否包含开发。
- 用户回复数字后，将其视为最近一组尚未处理的编号选项的完整回答并立即执行，不要求复述长句，也不重复确认；执行后该组编号立即失效，后续数字不得回指已经处理的旧选项。只有范围、风险或外部影响发生实质变化时，才重新列出编号选项请求确认。

## 项目级交付授权

仓库所有者已授权自动执行微信真机预览。预览工具成功只表示预览包已生成或发送，必须按 [交付流程](references/delivery.md) 核对本轮构建凭据；用户确认手机已显示本轮变化后，才能表述为“真机已更新”。

普通 commit 必须等待用户确认：提交前审查 status、diff 和未跟踪文件，向用户说明每个逻辑批次的范围与建议提交信息；用户明确同意后，才按已告知方案创建 Conventional Commits。用户确认提交即同时授权提交成功后普通推送当前分支，不再单独询问是否推送；只有用户明确选择“只本地提交”时才不推送。

提交批次按逻辑边界决定：同一目标且相互依赖的代码、测试和文档可同批；不同目标、可独立理解或回滚的改动分批。当前任务无关的用户改动始终保留在工作区，不得夹带提交。

提交前若当前分支已领先远端，必须在编号确认选项中说明推送将包含的既有提交数量；用户选择提交并推送后，该选择同时覆盖已披露的既有提交。确认只覆盖已告知的批次和推送范围，范围变化时须重新列出编号选项确认。

授权不覆盖 force-push、历史重写、删除分支、发布体验版/正式版或夹带无关改动。
