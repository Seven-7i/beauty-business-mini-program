# 领域文档

本文件规定工程技能在探索和修改仓库时如何使用领域文档。

## 开始工作前

- 阅读仓库根目录的 `CONTEXT.md`。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策记录。
- 如果某个文件不存在，继续工作即可，不需要预先创建或报告缺失。

## 文档结构

本仓库采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

如果未来演变为大型多包仓库，可在根目录增加 `CONTEXT-MAP.md`，由它指向各上下文自己的 `CONTEXT.md` 和 ADR。

## 使用统一的领域词汇

在 Issue 标题、重构方案、问题假设、测试名称和代码命名中，应使用 `CONTEXT.md` 已定义的术语，不要改用其中明确要求避免的同义词。

如果需要的概念尚未出现在词汇表中，应先判断它是无意引入的新说法，还是确实存在的领域缺口；真正的缺口可交由 `domain-modeling` 技能补充。

## 标明与 ADR 的冲突

如果方案与现有 ADR 冲突，必须明确指出冲突的 ADR 和原因，不得静默覆盖已有决策。
