# 微信小程序需求文档

> 文档状态：需求已确认  
> 更新时间：2026-07-22

## 1. 项目背景与边界

本项目是供个人使用的美容业务微信小程序，包含库存物品、服务项目、顾客、预约执行、轻量经营统计和个人设置。

本期唯一交付平台是微信小程序。不建设服务端、云数据库、登录系统、在线支付或多人协作；全部业务数据保存在当前设备本地。用户可以主动导出未加密 JSON 备份，并按文件声明的完整系统或选择模块范围恢复数据。

业务记录只包含文字、数字、时间、状态和关联 ID 等结构化数据。不支持业务图片、头像、照片、视频或附件，也不提供拍照、相册、上传和媒体预览入口。

## 2. 模块与进入规则

### 2.1 美容模块

美容模块包含：

- 模块内首页、日程、报表和数据四个页签
- 首页与轻量经营统计
- 库存物品
- 服务项目
- 顾客管理
- 预约列表、月历与执行

### 2.2 全局导航与我的

已解锁至少一个业务模块后，全局底部导航只包含“工作台”和“我的”。工作台只展示已解锁模块入口；模块管理、系统级数据备份与本机容量管理统一放在“我的”。日程、报表和模块数据保护属于具体业务模块，不进入全局底部导航。

我的模块包含：

- 输入模块授权码
- 查看已解锁模块
- 多模块时设置默认进入模块
- 导出本地备份
- 查看最近导出时间
- 从备份文件恢复
- 查看本地存储占用和清理入口

### 2.3 模块授权

每个业务模块使用固定授权码进行本地解锁。授权码只控制本机功能入口，不属于安全授权或付费校验。

| 业务模块 | 授权码 |
| --- | --- |
| 美容模块 | `587960` |

规则：

1. 本地校验成功后立即解锁对应模块并持久保存。
2. 无效授权码提示“授权码无效”；重复输入提示“该模块已解锁”。
3. 第一版只允许增加已解锁模块，不允许主动移除。
4. 未解锁模块不展示入口，也不能访问其页面和数据。
5. 用户更换设备、删除小程序数据或清空缓存后，需要重新输入授权码，或直接从激活页恢复包含授权状态的备份。
6. 未解锁任何业务模块时进入模块激活页。
7. 已解锁至少一个业务模块时进入全局工作台，通过模块列表进入具体模块。
8. 全局页签状态与各模块内部页签状态相互独立；返回全局后由工作台承载模块入口，由“我的”承载模块管理、系统级数据保护和其他跨模块能力。

## 3. 本地数据、备份与恢复

### 3.1 本地数据边界

本地保存已解锁模块、个人设置、顾客、顾客地址、库存物品、库存变动、项目、预约和备份元数据。

限制：

1. 不同设备不自动同步。
2. 不支持多人或多设备共享同一份数据。
3. 删除小程序、清除数据或系统清理缓存后，未导出的数据可能丢失。
4. 系统不得自动或静默删除业务数据。
5. 容量紧张时只能提醒用户先导出，再由用户按日期手动清理历史记录。

容量验收目标：

| 数据 | 数量 |
| --- | ---: |
| 顾客 | 200 |
| 项目 | 50 |
| 库存物品 | 200 |
| 预约 | 2,000 |
| 库存变动记录 | 8,000 |

上述规模下全部本地数据目标不超过 7MB。达到 7MB 时显示导出和清理提醒，最终容量以真实模型生成的模拟数据测试为准。

### 3.2 导出备份

1. 备份为未加密 JSON，包含格式版本、生成时间、完整性校验和明确范围。完整系统备份包含设置、授权状态和所有模块；选择模块备份只包含所选模块数据。
2. 完整系统文件名为 `庄月空间系统备份_YYYYMMDD_HHmm.json`；美容模块文件名为 `庄月空间美容备份_YYYYMMDD_HHmm.json`。
3. 首次导出及每次恢复前提示文件包含顾客资料，请勿发送给无关人员。
4. 点击完整系统或模块导出入口后，先确认范围与未加密风险，再生成快照；文件生成后由用户明确点击“打开微信转发”。
5. 小程序不能读取通讯录、预选联系人或静默发送。
6. 只有完整系统文件由用户确认实际发送后更新“最近完整系统导出时间”和七天提醒基准；模块导出不能冒充完整系统备份。
7. 从微信转发面板返回后，无论微信 API 返回成功、取消或失败，都以强提示询问“已发送 / 未发送”；API 回调不能代替用户对聊天中实际结果的确认。
8. 若用户未处理确认就退出，待确认状态保存在当前设备；下次进入程序后再次弹出“上次导出尚未确认”，直到用户明确选择结果。
9. “已发送”决定先持久化再更新最近导出；决定一旦保存，后续清理失败只允许重试完成记录，不能再改选“未发送”。
10. 取消、失败或确认未发送均不更新最近导出时间，临时文件在流程结束后清理。

### 3.3 七天提醒

1. 没有业务数据时不提醒。
2. 从未导出过时，以首次保存业务数据的时间为基准；否则以最近导出时间为基准。
3. 满 7 个自然日后提醒，周期固定且不能永久关闭。
4. 用户可以“立即导出”或“稍后”。选择稍后后同一自然日不再提醒，第二天打开且仍到期时继续提醒。

### 3.4 恢复

1. 模块激活页、“我的”和模块内数据页提供与自身范围一致的恢复入口；全局工作台不重复提供恢复入口。
2. 完整系统备份整体恢复业务数据、已解锁模块和个人设置；选择模块备份只替换文件声明的模块数据，未选择模块、授权状态和个人设置保持不变。两种恢复都不逐条合并。
3. 恢复前校验格式、完整性、版本和实体字段。
4. 当前版本或受支持的旧版本备份可以迁移后恢复；由更新应用版本生成的备份提示先升级；未知或校验失败的文件拒绝恢复。
5. 当前设备在恢复范围内已有业务数据时，醒目提示将覆盖的准确范围，并提供“先导出当前数据”和“我已了解，继续恢复”。不强制先导出。
6. 用户确认后原子替换完整系统或所选模块并重建相关索引；任一步失败都保留恢复前的完整数据。

## 4. 库存物品

### 4.1 业务定义与页面

库存物品是美容服务中被持有、占用和消耗的一类物品，不代表一次采购行为。第一版不保存采购单价、供应商或采购批次。

页面包括列表、新增、编辑、详情、补货、盘点修正和库存变动记录。

### 4.2 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 与单位组成唯一标识 |
| 计量单位 | 是 | 离散单位或连续单位 |
| 初始库存 | 是 | 大于等于 0 |
| 备注 | 否 | 多行文本 |
| 状态 | 自动 | 启用或停用 |

离散单位如个、瓶、盒、片、支、次，只允许整数；连续单位如毫升、克，允许最多两位小数。

启用库存物品的“名称 + 单位”不可重复。物品被项目或预约引用后不能直接修改单位；需要换单位时停用旧物品并新建。

### 4.3 库存变动

每次实际库存变化形成轻量记录，系统保存类型、变动前数量、差额、变动后数量、时间和选填说明。

类型包括首次入库、补货、盘点修正、预约消耗：

- 补货：填写本次增加数量。
- 盘点修正：填写盘点后的实际库存，系统计算差额。
- 预约消耗：完成预约时自动生成。

个人手工产生的记录可以编辑或删除，但结果必须通过库存下限校验。预约消耗不能在库存记录中单独修改，只能更正对应预约。

### 4.4 占用与扣减

1. 待执行预约按实际用量占用库存，不实际扣减。
2. 可用库存为当前库存减去其他待执行预约占用。编辑预约时排除预约自身。
3. 预约用量不能超过可用库存。
4. 完成预约后按确认用量一次扣减，并生成预约消耗记录。
5. 取消或删除待执行预约会释放占用。
6. 当前库存不得小于 0，也不得低于其他待执行预约的占用量。
7. 校验失败时阻止操作，并显示各物品缺少数量。

### 4.5 停用和删除

已被项目或预约引用的库存物品只能停用；停用后不出现在新业务的默认选择列表，但历史继续显示。只有从未被其他业务记录引用的物品可以彻底删除。

## 5. 服务项目

### 5.1 页面与字段

页面包括列表、新增、编辑和详情。填写预约时允许快速新增项目，并在返回后保留预约草稿、自动选中新项目。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 项目名称 | 是 | 启用状态下唯一 |
| 标准价格 | 是 | 大于等于 0，零表示免费 |
| 预计服务时长 | 是 | 以分钟保存 |
| 项目默认用量 | 否 | 可为空 |

预计服务时长提供 30、60、90、120 分钟等快捷选项，也允许手动输入。

### 5.2 项目默认用量

默认用量是项目通常消耗的库存物品和建议数量，不占用或扣减库存。配置时可快速新增库存物品，至少填写名称、单位和初始库存。

每个默认用量必须大于 0，并符合物品单位精度。项目可以没有默认用量。

### 5.3 停用、删除和快照

已被预约引用的项目只能停用；未被引用的项目可以彻底删除。停用项目不出现在新预约中，但历史预约继续使用保存的项目名称、价格和时长快照。

停用项目与新项目重名时，重新启用前必须解决冲突。

## 6. 顾客管理

### 6.1 页面与字段

页面包括列表、新增、编辑和详情。预约表单支持快速新增顾客，成功后自动选中并保留预约草稿。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 昵称 | 是 | 所有未删除顾客中唯一 |
| 手机号 | 是 | 中国大陆 11 位手机号；所有未删除顾客中唯一 |
| 服务地址列表 | 否 | 每项包含地址正文和地址备注 |

手机号只校验中国大陆号码，不支持国际号码。列表直接显示完整手机号，不脱敏。

### 6.2 地址

顾客可以保存多个服务地址，不设置默认地址。创建预约时由用户手动选择一个地址，或填写临时地址；临时地址可以选择同时保存到顾客地址列表。

预约保存地址正文和备注快照，顾客以后修改地址不影响历史预约。

### 6.3 历史与停用

预约始终展示顾客当前昵称和手机号，不保存顾客资料快照。顾客详情展示历史预约、累计完成次数和累计成交金额。

已有预约的顾客不能彻底删除，只能停用；停用后不参与新预约选择，可重新启用。昵称和手机号在停用后仍然占用。只有从未关联预约的顾客可以彻底删除。

## 7. 预约执行

### 7.1 页面

包含预约列表、新增/编辑、详情、完成确认和预约月历。月历按月标记有预约的日期，点击后展示当天列表；第一版不做拖拽改期、周视图或时间轴排班。

### 7.2 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 顾客 | 是 | 关联一个启用顾客 |
| 项目组合 | 是 | 至少一个且不可重复 |
| 标准金额 | 自动 | 所选项目标准价格之和的快照 |
| 预计总时长 | 自动 | 所选项目预计时长之和的快照 |
| 实际物品用量 | 自动带出、可编辑 | 最终负责占用和扣减 |
| 预约开始时间 | 是 | 日期时间 |
| 服务地址 | 是 | 顾客地址或临时地址快照 |
| 备注 | 否 | 多行文本 |
| 状态 | 自动 | 待执行、已完成、已取消 |
| 成交金额 | 完成时是 | 待执行阶段不填写 |
| 实际完成时间 | 完成时是 | 默认当前时间，可修改 |
| 取消原因 | 否 | 快捷选项或文本 |

### 7.3 多项目与实际用量

1. 一个预约可以选择多个互不重复的项目。
2. 标准金额和预计总时长由项目快照相加。
3. 同一种库存物品的默认用量合并后形成预约实际用量。
4. 用户可以添加物品、移除默认项或修改数量。
5. 项目组合一旦增、删或替换，已有实际用量全部作废并按新项目重新生成，标准金额和预计总时长同步更新。
6. 待执行预约至少包含一个项目；找不到项目时可以快速新增。

### 7.4 状态和操作

**待执行**：占用库存。允许改期、编辑、完成、取消或删除。改期直接更新原预约，不增加独立状态。直接删除表示误建，需二次确认并释放占用；真实取消应使用取消操作。

**已完成**：确认服务已经发生并扣减库存。完成前必须在确认页核对实际用量、成交金额、实际完成时间和备注。成交金额默认带出标准金额；第一版不区分应收、已收、欠款或收款方式。

完成后允许更正实际用量、成交金额、实际完成时间和备注；用量更正同步补回或补扣库存。顾客和项目不能直接替换。误点完成时可二次确认后“撤销完成”，补回库存并恢复为待执行及库存占用。

**已取消**：释放占用、不扣库存。取消原因选填。误取消可以恢复为待执行；恢复前重新校验库存，不足时保持取消并显示缺少数量。已取消记录可二次确认后彻底删除，不改变库存。

删除已完成预约不会补回库存；对应库存消耗记录继续保留并标记来源预约已删除，经营统计不再包含该预约。误完成必须使用撤销完成。

### 7.5 时间冲突、逾期和提醒

1. 两个待执行预约按开始时间和预计总时长发生重叠时，显示警告但允许确认保存。
2. 冲突计算不包含上门路程或固定缓冲时间。
3. 计划开始时间已过但仍待执行时，派生显示“已逾期”并置顶；系统不自动完成或取消。
4. 第一版只做应用内提醒，不做微信消息通知。
5. 首页提醒区展示全部逾期、今天和未来三天的预约；更远预约从列表或月历查看。

## 8. 轻量经营统计

统计全部由未删除的已完成预约推导：

- 首页：本月完成预约数、本月成交金额、待执行预约数。
- 顾客详情：累计完成次数、累计成交金额。
- 月份归属使用实际完成时间，不使用预约开始时间。

第一版不记录支出、成本或利润，不提供账务和收款管理。

## 9. 数据关系与历史语义

- 顾客 1 对多 服务地址。
- 顾客 1 对多 预约；预约显示顾客当前资料。
- 预约多对多项目；预约保存每个项目的名称、价格、时长快照。
- 项目多对多库存物品；项目保存默认用量。
- 预约多对多库存物品；预约保存本次实际用量快照。
- 库存物品 1 对多库存变动记录。
- 停用业务对象仍为历史记录保留；只有从未被引用的对象可以彻底删除。

## 10. 验收摘要

1. 使用 uni-app、Vue 3、TypeScript 和 Composition API 构建并发布微信小程序。
2. 不依赖服务端、云数据库、登录、在线支付或媒体上传。
3. 模块授权、单/多模块进入规则和激活页恢复可用。
4. 顾客昵称与大陆手机号唯一，多地址与地址快照正确。
5. 库存单位精度、补货、盘点、占用、扣减及库存下限正确。
6. 多项目预约、项目快照、用量覆盖规则和快速新增流程正确。
7. 完成、撤销完成、取消、恢复取消、删除及库存联动正确。
8. 月历、冲突警告、逾期和应用内提醒正确。
9. 经营统计按实际完成时间与成交金额计算。
10. 未加密备份、七天提醒、兼容恢复和失败不覆盖正确。
11. 目标数据规模下总存储不超过 7MB，常用列表首次显示目标不超过 1 秒，搜索反馈目标不超过 300 毫秒。
12. 系统不自动删除任何业务数据，容量提醒和手动清理可用。

## 11. 实施顺序

1. 工程与微信真机能力验证：Storage、JSON 文件生成、微信转发、恢复选择和基础视觉。
2. 应用骨架、模块授权、本地数据层、迁移和备份恢复。
3. 库存物品、库存变动和项目。
