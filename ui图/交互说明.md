# 交互说明

## 0. 全局点击反馈

所有可执行操作的控件都必须在手指按下时立即给出可见反馈：原生按钮统一降低不透明度并轻微缩小，卡片、列表行、Tab、日期格、文字入口及其他非按钮操作区使用同等强度的 `hover-class` 按压态。已有页面专属按压色的控件继续保留专属反馈；禁用控件、仅阻止事件冒泡的内部区域和点击遮罩关闭弹层不模拟可执行按钮反馈。按压反馈只表达“已触摸”，不改变原有导航、提交和业务状态语义。

> 更新时间：2026-09-15

## 1. 通用规则

- 路由页面作为组合层，表单、选择器、列表、状态操作和确认弹层拆成聚焦组件。
- 表单草稿仅由当前页面持有；快速新增顾客、项目或库存物品返回后，原草稿不得丢失。
- 字段错误紧邻字段显示，首次提交定位到第一个错误。
- 保存、删除、状态变更、导出和恢复期间禁用重复点击。
- 成功使用短 Toast；失败说明原因和下一步，不清空表单。
- 返回前存在未保存修改时确认“放弃本次编辑？”。
- 删除、完成、撤销完成、取消、恢复取消和整体恢复使用明确动词的确认弹层。
- 当前已实现的业务数据以结构化字段为主；后续页面可按明确需求扩展图片或其他媒体能力。

## 2. 启动、模块与工作台

| 场景 | 反馈与去向 |
| --- | --- |
| 尚未解锁模块 | 展示模块码输入和“从备份恢复”；`587960` 解锁美容模块。 |
| 授权码无效或重复 | 保留输入，分别提示“授权码无效”或“该模块已解锁”。 |
| 只有一个模块 | 直接进入该模块，不展示默认模块设置；全局工作台保留为返回层。该行为已实现。 |
| 多个模块且无默认项 | 展示模块选择页。 |
| 多个模块且有默认项 | 直接进入默认模块，仍可手动切换。 |

第一版只允许添加模块，不提供移除入口。工作台只显示已解锁模块入口；模块管理、完整系统备份与恢复、本机容量和历史清理入口统一放在“我的”。美容首页显示本月完成数、本月成交金额、待执行数，以及全部逾期、今天和未来三天的预约。点击单条近期预约进入该预约详情，“查看全部”才进入预约执行列表；预约实体行通过浅粉底色、描边、内阴影与轻微缩放提供即时按压反馈。预约执行、顾客管理、服务项目和物品库存使用独立按钮卡片进入，并提供右箭头和按压反馈。

美容模块内“数据”页显示最近导出状态与七天导出建议；“导出美容模块”和“从备份恢复”是独立折叠入口，点击展开后分别复用既有生成、微信转发确认、文件校验和覆盖确认流程，再次点击当前入口时收起，点击另一入口时直接切换。入口展开时箭头转为向上，入口卡与下方浅紫内容面板形成连续层级。恢复当前有业务数据时，用户可先导出当前数据或明确确认后直接覆盖；不合并记录，不影响其他模块、个人设置或授权状态。未加密风险提示常驻，且在导出、恢复前仍执行明确确认。

## 3. 库存物品

### 3.1 列表与表单

- 列表支持按名称搜索和新增，“新增”按钮加号使用 `14px`；默认只展示启用物品，勾选“仅看停用”后只展示停用物品，行内展示名称、单位、当前库存、占用和可用库存。
- 点击物品卡片进入该物品的独立详情；启用物品卡片提供“补货”和“盘点修正”快捷操作，停用物品不提供库存调整入口。
- 物品详情顶部常驻当前库存、占用、可用库存和快捷调整；下方使用“物品资料 / 库存动态”双 Tab，首次进入默认展示库存动态，资料编辑与启停/删除操作收敛到“物品资料”。启停与彻底删除行统一使用左侧语义图标和右侧方向箭头，与服务项目详情保持一致。
- 列表“新增”和项目配置中的快速新增都进入原生导航标题为“新增库存物品”的独立页面；表单卡不重复标题或“取消”，“保存物品”作为卡片外页面级主操作。普通保存成功后返回库存列表；只有从仍在页面栈中的项目表单发起并通过一次性来源校验的快速新增，成功后才返回原项目表单、保留项目草稿并自动选中新物品，外部或过期链接按普通新增处理。
- 新增填写名称、单位、计量方式、初始库存和选填备注；启用对象的“名称 + 单位”不可重复。存在未保存草稿时使用微信原生返回确认“放弃本次编辑？”，保存中离开会明确提示原子写入仍将完成。
- 离散单位使用整数输入，连续单位允许最多两位小数。
- 已被引用的物品不能修改单位，只能停用后新建。
- 已被引用的物品只能停用；未被引用的物品可以二次确认后删除。

### 3.2 库存调整

- “补货”填写增加数量；“盘点修正”填写盘点后的实际数量。说明均选填。
- 列表卡片与物品详情中的“补货 / 盘点修正”都进入独立库存调整页；原生导航栏显示当前调整方式，页面顶部只保留一份物品库存概览，表单卡不重复物品名、当前库存或“取消”。
- 调整页允许在“补货增加 / 盘点修正”之间切换并同步原生标题；切换时清空数量草稿，避免把增加量误作实际库存提交。分段 Tab 与底部确认操作统一使用无微信原生默认层的语义控件，保留选中、禁用和按压反馈，避免真机叠加内部矩形色块。
- 两张独立表单有未保存草稿时，使用微信原生返回确认“放弃本次编辑？”；保存中离开会明确提示原子写入仍将完成，页面卸载后不再重复触发成功返回。
- 系统展示变动前、差额和变动后数量，并生成库存变动记录。
- “编辑资料”进入独立页面，原生导航栏承担标题与返回；资料卡只保留提示与字段，“保存修改”作为卡片外页面级主操作。该主操作与新增页统一使用无微信原生默认层的语义按钮，提交中禁用并保留按压反馈，避免真机出现文字后的矩形色块。停用和彻底删除仍只位于详情“物品资料”Tab。
- 每个物品详情只展示该物品自己的库存动态，按发生时间倒序排列；库存列表不在全部物品卡片后追加全局“最近变动”。以后若需要全局流水，可基于同一批库存变动记录按时间汇总，不改变当前数据结构。
- 库存动态生成后只读，不提供单条编辑或删除；补货、首次入库或盘点数量录错时，从物品详情发起新的“盘点修正”纠正当前库存并保留原始记录。
- 预约消耗记录只读，点击来源可以进入预约；来源预约已删除时显示“来源预约已删除”。

## 4. 项目

- 列表支持按项目名称搜索和新增；默认只展示启用项目，勾选“仅看停用”后只展示停用项目，不设置全部/启用/停用分段筛选。
- 项目卡片展示唯一名称、标准价格、预计时长和默认物品用量摘要；未配置时明确显示“未设置默认物品用量”。卡片不重复显示启用状态标签，停用项沿用低饱和整卡状态表达。
- 点击项目卡片进入独立详情；编辑、停用、重新启用和彻底删除等低频或风险操作集中在详情中，不堆叠在列表卡片上。
- 列表“新增”进入原生导航标题为“新增服务项目”的独立表单；详情“编辑资料”进入同一表单的编辑模式并预填现有资料。新增和编辑均把页面级保存操作放在表单卡外，编辑模式只切换标题、预填状态和保存文案。
- 表单中标准价格必填且允许 0 元；预计时长必填，提供 30/60/90/120 分钟快捷项。存在未保存草稿时使用微信原生返回确认“放弃本次编辑？”，保存中离开会明确提示原子写入仍将完成，页面卸载后不再重复触发成功返回；写入完成事件仍会刷新页面栈中的来源列表或对应详情，避免来源页停留在旧数据。
- 项目详情不设置 Tab；顶部常驻名称、启用状态、标准价格、预计服务时长和“编辑资料”，默认物品用量按物品逐项显示名称、数量和单位，未配置时展示明确空状态。
- 停用、重新启用和彻底删除集中在详情底部的“项目操作”；停用与删除继续二次确认，重新启用时复核启用名称唯一性和默认用量引用，业务失败保留详情并展示可读原因。
- 默认物品用量可以为空；每项数量大于 0 并遵循单位精度。
- 选择物品时可快速新增，保存后自动选中并保留项目草稿；一次性回传结果绑定发起它的项目编辑器，来源页卸载后清除，不能被其他项目草稿误领。
- 已被预约引用的项目只能停用；未被引用的项目可以删除。

## 5. 顾客与地址

- 顾客列表支持昵称和手机号搜索，完整显示手机号，不脱敏。
- 顾客列表默认只显示启用顾客；勾选“仅看停用”后只显示停用顾客，不设置全部/启用/停用分段筛选。
- 点击“新增”进入统一顾客表单页的新增模式，原生导航栏标题显示“新增顾客”；保存成功后返回并刷新顾客列表，直接返回时仍停留在原列表。点击顾客卡片进入详情，编辑入口以及停用、重新启用和彻底删除等低频或风险操作集中在详情中；启停与彻底删除行统一使用左侧语义图标和右侧方向箭头，与服务项目、物品详情保持一致。点击“编辑资料”进入同一顾客表单页的编辑模式，预填当前资料，原生导航栏标题显示“编辑顾客”，保存或返回后回到当前顾客详情。
- 列表卡片不重复显示状态标签；停用顾客使用低饱和灰色整卡和昵称删除线表达状态，手机号、服务地址与累计数据仍保持可读。
- 昵称和中国大陆 11 位手机号在全部未删除顾客中分别唯一；停用后仍占用。
- 顾客可以维护多个服务地址，每项包含地址正文和地址备注，不设置默认地址；点击顶部“添加地址”后，新地址插入列表首位；移除全空地址时直接删除，正文或备注已有内容时先二次确认。
- 已有预约的顾客只能停用；未关联预约的顾客可以删除。
- 顾客详情展示当前资料、地址、历史预约、累计完成次数和累计成交金额。
- 顾客详情顶部常驻当前资料、累计完成次数和累计成交金额；下方分为“顾客资料”和“历史预约”两个 Tab，默认选中“顾客资料”。“顾客资料”包含服务地址和资料操作，“历史预约”包含该顾客的预约历史，切换 Tab 只替换下方内容。
- 双 Tab 的选中指示条使用按钮内部独立节点并固定在 Tab 底边，不复用微信原生 `button::after`，避免开发者工具与真机的伪元素布局差异使指示条覆盖文字。
- 顾客详情顶部的完整手机号使用“电话图标 + 完整号码 + 拨打”的浅雾紫轻量胶囊，并提供按压反馈；用户点击后通过 `uni.makePhoneCall` 唤起系统拨号界面，调用失败时提示“未能打开拨号界面”，不静默拨号。
- 顾客详情缺少顾客标识或顾客已不存在时展示“返回顾客列表”；存在上一页时返回原列表，作为深链根页面进入时重建到顾客列表。删除成功沿用相同兜底。
- 编辑顾客资料期间从后台回到前台时不重新加载顾客快照，保留统一表单页中的未保存草稿和离开保护；保存成功返回详情后由详情页刷新当前资料。
- 点击保存后，昵称、手机号、地址输入及地址增删操作立即锁定，避免提交期间继续修改但未被本次写入包含；保存失败后恢复编辑和未保存草稿保护。保存尚未完成时若用户确认离开，已开始的写入仍会完成，但表单页卸载后不再自动执行第二次返回；写入完成后通过顾客保存事件刷新仍在页面栈中的列表或对应详情。
- 预约中快速新增顾客成功后自动选中；重名或重复手机号时引导查看已有顾客。

## 6. 预约创建与编辑

1. 选择一个顾客；找不到时可快速新增。
2. 选择至少一个互不重复的项目；找不到时可快速新增。
3. 新增页缺少启用顾客或启用服务项目时，空状态说明只列出当前缺失项，并逐项提供“新增顾客”或“新增服务项目”入口；两项都缺失时同时展示两个入口，返回新增页后自动刷新可选资料。
4. 服务项目通过底部多选面板选择，项目名称、价格和时长在左侧，右侧使用受面板临时状态直接控制的 uview-plus 勾选框；可搜索、逐项或整行勾选，并在“确认选择”后一次性回填项目组合。系统随即汇总标准金额、预计总时长和预约预计用量；普通新增/编辑页不展示“本次实际用量”，预计用量只用于待执行库存占用。
5. 项目组合发生任何变化时，预约预计用量按新项目默认用量重新生成；标准金额和预计总时长同步更新。
6. 手动选择顾客服务地址或填写临时地址；临时地址可选择同时保存给顾客。地址必填。
7. 选择预约开始时间，填写选填备注后保存。

时间与另一待执行预约重叠时展示冲突明细，用户可以取消或确认继续；只计算服务时段，不计算路程。改期直接编辑原待执行预约。

预约列表只提供统一“新增”入口，新增按钮中的加号使用与其他列表一致的 `14px` 尺寸。待执行、已完成和已取消三个状态 Tab 各自展示对应总数；不重复展示当前筛选或搜索结果数，也不提供月历入口，月历仅从美容模块的“日程”页进入。已完成 Tab 内不再为普通记录重复展示“已完成”标签；后补完成记录只展示“后补”标识，仍可与普通完成记录区分。进入新增预约页后，顶部先选择“正常预约 / 后补预约”，默认选中正常预约；正常模式不显示完成情况和本次实际用量。预约类型与后补完成情况均使用无微信原生按钮默认层的语义分段控件：外层统一承担边框和圆角，正常预约、后补预约、已完成和未完成的任一选中项都统一使用浅紫底、紫色文字和勾选图标，不出现独立内描边。切换到后补模式后保留后补标识，并显示“已完成 / 未完成”选择，默认选中已完成，绝不提供待执行选项。已完成时展示并必填本次实际用量、成交金额和实际完成时间，实际用量默认带出项目默认用量；未完成表示顾客取消，隐藏完成专属字段，必须填写取消原因，保存后直接成为带后补标识的已取消预约，不占用或扣减库存。后补标识保存后不可取消，并在预约列表和详情中展示。

预约详情的“预约信息”各行固定为左右两列：左列为紧凑的图标和字段名，右列为比字段名更大的 `27rpx` 右对齐字段值；行内间距和上下留白保持紧凑，项目组合、服务地址、备注和取消原因等长内容只在右列换行，不挤压字段名。顶部顾客手机号完整展示为带电话图标和“拨打”文案的按钮，点击后通过 `uni.makePhoneCall` 唤起系统拨号界面；按钮提供压暗、描边和轻微缩放的按压反馈，唤起失败时提示“未能打开拨号界面”并保留当前详情页。

## 7. 预约状态操作

### 待执行

- 占用但不扣减库存。
- 计划时间已过时派生显示“已逾期”并置顶，不自动改变状态。
- 可以编辑、改期、完成、取消或删除。
- 删除表示误建，二次确认后释放占用；真实取消使用取消操作。

### 完成

普通预约点击“完成预约”后打开确认弹窗，在弹窗中编辑本次实际用量、成交金额、实际完成时间和备注。本次实际用量优先带出该预约创建时按项目默认用量生成的预计用量；历史预约未保存该快照时，回退带出当前项目的正常用量。选择一个尚未列入实际用量的库存物品时，系统立即新增一条空用量行，用户只需填写该行数量，不再额外点击“添加”；每条已有用量也可重新选择物品，选择器保留当前行的物品但隐藏其他行已选物品，替换物品后保留该行已填写数量。成交金额默认带出标准金额，完成时间默认当前时间。点击确认时，金额、完成时间和每条无效用量分别在对应字段旁显示错误；库存不足等需实时数据才能判断的错误显示在实际用量区。库存不足时禁止确认并显示缺少数量。

完成后允许更正上述四项；更正用量自动补回或补扣库存。顾客和项目不能直接替换。正常预约误点完成时使用“撤销完成”，补回库存并恢复完成前保存的预计用量占用；后补完成不可撤销为待执行。

删除已完成预约不会补回库存；库存消耗记录继续保留，经营统计移除该预约。

### 取消

取消原因必填，可使用“顾客临时有事、身体不适、时间冲突、其他”等快捷项，选择其他时填写具体说明。普通取消后释放占用；后补预约选择未完成时直接保存为已取消，不产生待执行占用。

正常预约误取消时可恢复待执行；库存不足则阻止恢复并显示缺少数量。后补取消不可恢复为待执行。已取消记录可二次确认后删除，不改变库存。

## 8. 月历与提醒

- 月历标记存在预约的日期，点击日期展示当天列表；“今天”回到真实今天所在月份并选中当天，切换月份默认选中新月份 1 日；月历区支持上滑收起为当前周、下滑展开整月，左右滑动按当前形态切换上/下周或上/下月；不做拖拽改期或时间轴排班。
- 第一版只有应用内提醒，不发送微信消息。
- 首页提醒区显示全部逾期、今天和未来三天的预约。

## 8.1 轻量经营报表

- 报表默认展示设备本地当前自然月，月份标题使用“年 + 月”完整格式；点击左箭头查看上一个自然月，点击右箭头返回下一个自然月，当前月的右箭头禁用，不允许进入未来月份。
- 月份切换使用已读取的本机预约快照即时重算已完成、成交金额、客单价、较上月和服务贡献，不需要重复读取存储。
- 汇总卡展示已完成单数、成交金额、客单价和较上月成交金额变化；上月无成交时环比显示“—”，不制造百分比。
- “较上月”遵循国内股票颜色习惯：上涨为红色、下降为绿色，持平 `0%` 或无法对比的 `—` 使用灰色。
- 服务贡献最多展示三项，按贡献金额降序排列；多项目预约按项目标准价格占比分摊本次实际成交金额。没有已完成服务时展示独立空状态，不生成示例数据。
- 删除已完成预约后，该预约从汇总与服务贡献中移除；更正成交金额或实际完成时间后，重新进入报表即按最新数据派生。

## 9. 备份、容量与恢复

### 七天提醒

- 有业务数据且距首次数据或最近导出满七个自然日时提醒。
- 周期不可关闭或修改；“稍后”后同一自然日不再出现，第二天仍到期则继续提醒。

### 导出

1. 点击“完整系统备份”或“选择模块导出”后，先展示准确范围和未加密文件提示；用户确认“生成备份”后才开始生成文件。
2. 生成带格式版本和完整性校验的 JSON，再明确展示“打开微信转发”；不使用动态出现的“立即导出”按钮。
3. 用户手动选择联系人；小程序不读取通讯录、不预选或自动发送。
4. 从微信转发面板返回后，无论 API 返回成功、取消或失败，都立即弹窗询问“已发送 / 未发送”；只有用户明确选择“已发送”才记录最近导出时间。
5. 若用户没有处理弹窗便退出，保留本机待确认状态；下次进入程序后再次弹出“上次导出尚未确认”，直到明确选择结果。
6. 同一次程序启动只显示一份上次导出确认；处理完成后不立即叠加容量或七天备份提醒，避免连续点击两次弹窗。
7. 用户选择“已发送”后先锁定该决定；若记录或清理失败，只展示“继续完成导出记录”，不再允许改成“未发送”。
8. 取消、失败或确认未发送不更新最近导出时间；模块导出确认发送也不更新完整系统导出基准。

### 恢复

- 激活页和“我的”均可选择备份文件。
- 校验通过后展示文件时间、版本和数据摘要。
- 已有数据时提供“先导出当前数据”和“我已了解，继续恢复”。
- 恢复整体替换业务数据、模块授权和设置；失败保持当前数据不变。
- 旧版备份迁移后恢复；未来版本提示升级；未知或损坏文件拒绝恢复。

### 容量

- 达到 7MB 时显示导出和手动清理提示，不自动删除数据。
- 历史清理按日期和状态筛选；各状态删除后的库存语义按需求文档执行。
