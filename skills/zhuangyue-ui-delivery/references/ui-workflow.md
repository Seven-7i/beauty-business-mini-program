# UI 工作流

## 设计先行

- 新页面或新风格先产出候选图，用户确认方向后再改代码。
- 需要位图设计稿时使用 ImageGen；画布比例参考最近确认的同平台手机页面，生成后检查中文、层级、裁切和安全区。
- 候选图和定稿直接保存到仓库 `ui图/`；聊天只报告文件名和状态，不重复展示图片。
- 文件名使用 `NN-页面-方向-vN.png`：`NN` 取下一未使用的两位序号，同一页面迭代递增版本号；确认状态记录在 `UI说明.md`，确认时不机械改名。
- 每个页面长期只保留一张已确认定稿；评审中最多额外保留最新候选。新稿确认后，核对页面归属并移除淘汰稿。
- 候选图生成后立即在 `ui图/UI说明.md` 标记“待确认”；用户确认后再更新当前定稿和关键视觉决策。
- 交互提案确认后才写入 `ui图/交互说明.md` 和必要的需求文档；用户已单独明确交互规则时可立即记录。
- 用户放弃某个候选方向时，删除该未确认图并从 `UI说明.md` 移除对应“待确认”索引，不影响既有定稿。

## 风格隔离

- 全局工作台是模块门厅；“我的”是本机控制中心。两者及系统级子页面使用同一平台视觉语言，但不继承美容模块风格。
- 每个业务模块可以拥有自己的风格。修改全局页面时不扩散到模块内部；修改模块页时不重做全局壳。
- 具体颜色、层次、图标和已确认页面以 `ui图/UI说明.md` 为唯一视觉说明，不在本参考重复缓存。

## 零图片运行时

- PNG/JPG/WebP 等图稿只用于评审，不进入 `app/src` 或编译包。
- 页面不使用 `<image>`、位图背景、远程字体图标或 `data:image/*`。
- 图标调用语义化 `AppIcon`；新增图标在组件内部用 SVG/CSS 线条统一画布实现，调用页面不做逐图标位置补丁。
- 模糊、环境光和材质层次由 CSS 颜色、透明度、描边、阴影与 `backdrop-filter` 构成。

## 实现检查

- 只实现已确认页面和用户点名的交互，不补造未确认模块、指标或管理入口。
- 视觉实现以最近确认的同平台设计稿为参照，不把某个业务模块的风格错误扩散到系统页面。
- 真机优先检查安全区、固定导航遮挡、图标居中、长文案换行、弹窗是否重复及异步状态是否可恢复。
- 用户报告真机问题时，先建立能抓住原症状的回归测试，再修复并重新推送。
- 模拟器可用于自检；`auto_preview` 成功只代表包已推送，真机视觉是否通过以用户反馈为准。
